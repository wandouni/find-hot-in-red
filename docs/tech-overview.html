🧩 浏览器插件 — 核心采集引擎 02

基于 Chrome Manifest V3，插件是整个系统的数据入口。设计目标：用最自然的方式模拟真实用户行为，在不触发平台风控的前提下完成批量采集。

🗂️ 文件职责划分

文件 运行环境 注入时机 核心职责
manifest.json 配置 — 声明权限、注入规则、Service Worker 指定
popup.html/js 扩展页面 用户点击图标 关键词输入、数量设置、日期筛选、启动/停止、进度展示
interceptor.js MAIN world document_start（最早） 劫持 fetch / XHR，从 XHS API 响应里提取 token + 发布时间
background.js Service Worker 常驻后台 主控循环：导航、等待、抓取 DOM、批量上报
content.js isolated world document_idle 辅助 DOM 操作（备用）
config.js 常量 — 后端 URL、延迟范围、最大数量
💡 为什么需要 MAIN world？
Chrome MV3 的 Content Script 默认运行在 isolated world，无法访问页面原始的 window.fetch。interceptor.js 必须在 MAIN world 运行，才能在 XHS 自己的 JS 加载前替换原生 fetch/XHR，从而拦截其 API 响应。

⚙️ Service Worker 主控流程（background.js）

收到 START_TASK 消息后，background.js 按以下步骤驱动采集：

  • 1
    创建方案（Task） 向后端 POST /api/tasks 注册本次采集任务，获得 task_id，后续所有笔记都归属该方案，方便前端按方案隔离展示。
  • 2
    逐关键词处理 对每个关键词构造 XHS 搜索 URL（含 sort=time_descending），调用 chrome.tabs.update 导航到搜索结果页。 
    const searchUrl =
  `https://www.xiaohongshu.com/search_result`
  + `?keyword=${encodeURIComponent(keyword)}&type=51`
  + (dateFilter > 0 ? '&sort=time_descending' : '');
  • 3
    点击 XHS 原生日期筛选按钮 调用 applyXHSDateFilter()，用 executeScript 向页面注入 JS，查找"发布时间"区域内的筛选按钮并触发 MouseEvent('click')，让 XHS 自己过滤掉旧内容，从源头减少无效访问。
  • 4
    读取 interceptor.js 捕获的链接 调用 getCapturedLinks(tabId)，在 MAIN world 读取 window.__xhsLinks，拿到笔记 ID、URL 和发布时间戳。对每条链接先做 API 时间戳预过滤（passesTimePreFilter），跳过超期笔记，无需打开其页面。
  • 5
    访问笔记页，抓取 DOM 导航到单篇笔记，等待加载完成，调用 scrapeCurrentPage() 提取标题、正文、作者、点赞数、收藏数、发布日期、前 10 条热评。
  • 6
    二次日期验证 用 parseDaysAgo(note.publish_date) 解析页面上的中文日期（"刚刚"、"3小时前"、"昨天"等），若 daysAgo 为有限数且超出筛选窗口则丢弃。无法解析的日期（返回 Infinity）不丢弃，继续保留。
  • 7
    批量上报后端 每个关键词采集结束后，调用 pushNotes(collected, taskId)，一次性 POST /api/notes，后端执行 upsert 避免重复。
  • 8
    更新方案状态 所有关键词处理完后，PATCH /api/tasks/{id} 将方案状态标记为 done，前端刷新时显示"已完成"。

🔍 API 拦截机制（interceptor.js） 03

这是整个插件最精密的技术模块。它在 XHS 任何 JS 执行之前，就偷梁换柱地替换了浏览器原生的网络请求方法，使得 XHS 的每次 API 返回都对我们透明可见。

⚠️ 为什么不能在 background.js 里直接调 XHS API？
XHS 的搜索/详情 API 有严格的签名校验（x-s、x-t 等请求头由前端 JS 动态生成），且 xsec_token 只在页面内 JS 调用 API 时出现在响应里。直接 fetch 无法绕过签名，也拿不到 token。唯一可靠方式是"搭便车"——让 XHS 自己的 JS 发请求，我们在旁边截获响应。

🔧 实现原理：Monkey Patch

在 document_start 阶段，XHS 的任何 JS 还未加载，此时替换原生方法，XHS 后续调用的就是我们的包装版本：

interceptor.js(function () {
  // 共享存储: { noteId → { url, time } }
  window.__xhsLinks = window.__xhsLinks || {};

  /** 统一时间戳为毫秒：XHS 部分接口用秒，部分用毫秒 */
  function toMs(t) {
    const n = Number(t);
    // 秒级时间戳 < 1e12，毫秒级 ≥ 1e12
    return n < 1_000_000_000_000 ? n * 1000 : n;
  }

  function extractTokens(data) {
    const items = data?.data?.items ?? data?.items ?? [];
    items.forEach(item => {
      const id    = item?.id || item?.note_id;
      const card  = item?.note_card ?? item?.noteCard ?? {};
      const token = item?.xsec_token ?? card?.xsec_token;
      // 发布时间：多字段兜底，适配 XHS 不同版本的响应结构
      const rawTime = card?.time ?? card?.create_time
                   ?? item?.time ?? item?.create_time ?? 0;

      if (id && token) {
        window.__xhsLinks[id] = {
          url: 'https://www.xiaohongshu.com/explore/' + id
               + '?xsec_token=' + encodeURIComponent(token)
               + '&xsec_source=pc_search',
          time: toMs(rawTime),   // Unix 毫秒
        };
      }
    });
  }

  /* ── 劫持 window.fetch ──────────────────────────────────── */
  const _fetch = window.fetch;
  window.fetch = async function (...args) {
    const resp = await _fetch.apply(this, args);
    resp.clone().json().then(extractTokens).catch(() => {});
    return resp;  // 原样返回，XHS 感知不到任何变化
  };

  /* ── 劫持 XMLHttpRequest.send ───────────────────────────── */
  const _send = XMLHttpRequest.prototype.send;
  XMLHttpRequest.prototype.send = function (...args) {
    this.addEventListener('load', () => {
      try { extractTokens(JSON.parse(this.responseText)); } catch {}
    });
    return _send.apply(this, args);
  };
})()

🌉 background.js 如何跨 world 读取

Service Worker 与 MAIN world 互不可见，需通过 executeScript 桥接：

background.jsasync function getCapturedLinks(tabId) {
  const results = await chrome.scripting.executeScript({
    target: { tabId },
    world:  'MAIN',           // 进入页面的 JS 上下文
    func:   () =>
      Object.entries(window.__xhsLinks || {})
             .map(([id, val]) => ({
               id,
               url:  typeof val === 'string' ? val : val.url,
               time: typeof val === 'string' ? 0   : val.time,
             })),
  });
  return results[0]?.result || [];
}
✅ 设计亮点：window.__xhsLinks 是一个幂等的字典，多次滚动触发多次 XHS API 调用，数据会不断追加进来。background.js 每轮只取"新增"的（用 seenIds Set 去重），实现了增量抓取，不会重复访问同一篇笔记。

🛡️ 反检测 & 拟人化策略 04

XHS 对机器人访问有严格的频率检测和行为分析。我们在每个环节都注入了随机性，使采集轨迹与真实用户高度相似。

阅读时间模拟

三段式随机分布，模拟浏览型/阅读型/深度阅读型用户

function readingDelay() {
  const r = Math.random();
  if (r < 0.4)  // 40%: 快速浏览
    return sleep(rand(5000, 12000));
  if (r < 0.75) // 35%: 正常阅读
    return sleep(rand(12000, 25000));
               // 25%: 深度阅读
  return sleep(rand(25000, 40000));
}
仿人滚动

2-4 次不规则小滚动 + 25% 概率向上回滚（模拟重新看了一眼）

async function humanScroll(tabId) {
  const passes = 2 + Math.floor(Math.random() * 3);
  for (let i = 0; i < passes; i++) {
    await scrollBy(rand(250, 750));
    await sleep(rand(600, 1600));
  }
  if (Math.random() < 0.25)  // 25% 向上回滚

}

  • 30% 概率在笔记页内向下滚动（模拟看评论）

🗓️ 多层日期过滤

第一层：XHS 原生筛选（UI 点击）

点击筛选按钮后，XHS 的搜索 API 本身就只返回时间范围内的笔记，interceptor.js 捕获的链接已经是预过滤结果。

第二层：API 时间戳预过滤

interceptor.js 捕获了 API 响应中的 note_card.time，background.js 用它与截止时间对比，直接跳过超期笔记，无需打开其页面。

function passesTimePreFilter(timeMs, dateFilter) {
  if (!dateFilter || !timeMs) return true;
  const cutoff = Date.now() - dateFilter*24*3600*1000;
  return timeMs >= cutoff;
}
第三层：DOM 日期验证

打开笔记页后，从 DOM 提取发布日期文字，用 parseDaysAgo() 解析（支持"刚刚"/"3小时前"/"昨天"/"MM-DD"/"YYYY-MM-DD"），再次验证后丢弃超期笔记。无法解析的日期不丢弃（保守策略）。

🗑️ 级联删除

SQLite 默认不开启外键级联，后端手动按依赖顺序删除：评论 → 笔记 → 方案。

routes/tasks.pydef _cascade_delete_task(task_id: int, db: Session):
    note_ids = [row[0] for row in db.query(Note.id)
                .filter(Note.task_id == task_id).all()]
    if note_ids:
        db.query(Comment).filter(Comment.note_id.in_(note_ids))
          .delete(synchronize_session=False)
        db.query(Note).filter(Note.task_id == task_id)
          .delete(synchronize_session=False)
    db.query(Task).filter(Task.id == task_id)
      .delete(synchronize_session=False)
